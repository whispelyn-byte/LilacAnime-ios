## RE:Anime 끊김

RE:Anime 영상은 FlixCloud CDN(Cloudflare, `vault-*.zenithcdn.top`)에서 `.png`/`.webp`로 위장한 조각으로 옵니다. 이 PC에서 확인한 결과 응답은 시애틀 엣지에서 오고, 요청 하나가 약 0.3MB/s를 받습니다. 데스크탑은 조각을 여러 범위로 나눠 HTTP/1.1 연결 여러 개로 동시에 받아 이를 보완합니다.

iOS는 같은 방식으로 나눠 받았지만 `URLSession.shared`가 Cloudflare와 HTTP/2로 연결 하나에 모든 요청을 실었습니다. 지금 조각과 앞으로 받을 5개 조각(영상·음성 각각), 조각마다 최대 6개 범위가 한 연결을 나눠 쓰면서, 플레이어가 기다리는 조각은 대역폭의 일부만 받았습니다. 3초 동안 데이터가 없으면 같은 범위를 다시 요청하는 감시가 이 대기를 멈춤으로 보고 요청을 더 늘렸습니다. 재생을 시작하거나 탐색한 직후 가장 심했습니다.

- 영상 요청을 세션 6개에 번갈아 보내 연결을 나눴습니다(쿠키 저장소는 공유).
- 다음 조각 미리 받기는 플레이어가 기다리는 조각을 받은 뒤 시작합니다.
- 다른 소스의 일반 조각·재생목록(Animenosub, 애니24, 링크애니 등)은 12초 동안 데이터가 없으면 다시 요청합니다(최대 3번). 전에는 60초 동안 기다린 뒤 실패해 재생이 1분 멈췄습니다.
- 디코딩은 이미 VideoToolbox 하드웨어(HEVC 10비트 포함)라 바꾸지 않았습니다.
