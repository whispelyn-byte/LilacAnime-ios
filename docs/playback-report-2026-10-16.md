- 첫 사진의 여러 줄 자막은 사용자가 노래 연출일 수 있다고 정정했다. 자막 내용·스타일·가사 배치는 변경하지 않았다.
- 두 번째 사진은 검은 화면 왼쪽 아래에 영상 일부만 보이는 상태다. 원본 다운로드 파일은 첨부되지 않아 파일 손상 여부는 확인하지 못했다.
- 추가 제보: iOS에서 자막이 간헐적으로 깜박이며 일시 정지 상태에서도 발생한다. 해당 현상을 담은 영상/기기 로그는 없다.

## 변경

1. `MPVSurface`는 UIKit의 backing layer와 분리한 Metal 하위 레이어를 사용한다. 창과 유효한 화면 크기가 정해진 뒤에 mpv를 연결한다. 화면 배치에서는 암묵적 Core Animation 애니메이션을 끄고, 실제로 달라진 크기·배율만 반영한다. 화면 회전·다운로드 재생 시작 시 출력 크기 불일치와 정지 화면 배치 중 깜박임의 의심 경로를 줄이는 수정이다. 실기기에서 제보 증상이 해결됐다고 검증한 것은 아니다.
2. 기존 MoltenVK 1×1 drawable 방어는 유지하고 비정상 실수 및 같은 크기의 중복 설정도 거른다. [MPVKit MetalLayer](https://github.com/mpvkit/MPVKit/blob/main/Demo/Demo-iOS/Demo-iOS/Player/Metal/MetalLayer.swift), [mpv #13651](https://github.com/mpv-player/mpv/pull/13651)를 대조했다. 기존 코드에도 1×1 방어가 있었으므로 이를 새로 발견한 원인으로 간주하지 않는다.
3. 자동 OP/ED 건너뛰기는 일시 정지·버퍼링 중 실행되지 않으며 그 시간은 2.5초 대기 시간에 포함하지 않는다. 사용자의 후속 요청대로 이미 시청한 시간은 유지한다. 예를 들어 1초 시청 후 정지하면 재생 후 남은 1.5초만 기다린다. 재생 위치의 실제 증가량을 배속으로 나누어 시간을 누적하므로 정지/버퍼링 시간은 늘어나지 않는다. 탐색이나 구간 변경은 새로 계산한다. 기존 코드는 정지 중에도 계속되는 진행 콜백에서 벽시계 시간으로 seek를 실행할 수 있었다. 이 수정이 소리만 건너뛰는 제보의 원인을 입증하지는 않는다.
4. 사용자가 영상의 실제 문제를 ‘선택 목록을 스크롤하면 다시 위로 올라감’으로 명확히 했다. 앞서 넣었던 필터 중복 제거와 그 검사는 되돌렸다. 모든 원래 항목/서버 값을 보존한다. `CatalogSelect`의 긴 네이티브 메뉴를 별도 선택 창의 ScrollView로 바꾸고, 창을 열 때 항목을 복사해 카탈로그 백그라운드 갱신과 분리한다. 선택·닫기를 지원하며 선택한 서버 값을 기존 draft 바인딩에 그대로 전달한다. 실기기 재현 검증은 아직 하지 못했다.

## 검증과 남은 확인

- XCTest 회귀 검사 추가: 회전·반복 배치·0/1 크기 방어, 정지/버퍼링 후 자동 건너뛰기 대기 시간, 선택 창의 부모 갱신 후 실제 UIScrollView 위치 유지 및 모든 원래 필터 항목 보존.
- 현재 Windows 작업 환경에는 Swift/Xcode/iOS 시뮬레이터가 없다. 위 XCTest와 iOS 빌드 및 실기기 검증은 실행하지 못했다. IPA를 생성하거나 배포하지 않았다.
- 실기기에서 다운로드 영상을 열고 회전·설정 패널 표시를 반복해 전체 화면 출력 크기를 확인해야 한다. 자막을 정지 상태로 두고 패널 표시/숨김과 번역 업데이트를 각각 확인해야 한다.
- 소리만 건너뛰는 현상은 발생 작품·회차·재생 시각, 스트리밍/다운로드 여부 및 재생 로그가 필요하다. 오디오 버퍼/동기화 설정은 추정으로 변경하지 않았다.
